# AstrBot 群聊主动回复管理

让机器人只在值得接话时主动加入群聊，减少复述、报时、强行吐槽和无意义回应。

插件负责判断“这条普通群消息值不值得回应”。真正生成回复时，仍使用当前会话的人格、模型和上下文。判断拿不准或调用失败时，本次不主动回复。

目前支持 QQ/OneBot v11（`aiocqhttp`）。

## 它做什么

没有直接唤醒机器人的普通群消息，会先等待一小段安静时间，再经过范围、回复间隔和概率筛选，由模型判断是否适合参与。等待期间出现新消息时，旧消息不再单独触发判断，改为从最新消息重新计时。正文中出现配置的机器人称呼时，不等待且跳过概率抽取，但模型仍可以选择不回复。机器人被明确叫到后，会在同一群短时间保持参与；此后每次真正回复都会重新计时。

直接 @ 机器人、引用机器人消息或使用唤醒前缀时，默认交给 AstrBot 的正常回复流程。本插件不会替代这条流程；群黑名单和账号黑名单是例外，它们会在正常回复之前拦截消息，因此也能阻止这些直接唤醒。

## 推荐用法

在 AstrBot 中建议这样搭配：

- 开启“群聊消息记录注入上下文”，让最终回复了解近期群聊；
- 多人群聊开启“用户识别”，便于模型区分当前发送者；
- 关闭 AstrBot 自带的“主动回复”，由本插件负责普通群消息的主动参与。

群聊上下文不是插件运行的硬性条件，但关闭后，最终回复能参考的群聊背景会更少。如果 AstrBot 自带主动回复仍处于开启状态，插件会暂停该会话中的主动参与，避免两套机制重复回复。

初次使用可以从默认的 15% 参与判断概率和 80% 回复把握要求开始，再根据群聊活跃程度调整。

## 工作原理

普通群消息大致经过以下过程：

1. 检查群范围和账号黑名单；
2. 保存一小段近期消息，供“是否值得接话”的判断参考；
3. 短暂等待群聊说完；等待期间的新消息会替换旧的触发边界；
4. 检查回复间隔，再按参与判断概率抽取；明确出现机器人称呼时跳过概率抽取；
5. 如已开启图片查看，先由视觉模型生成图片描述；
6. 判断模型给出是否回复及把握程度；
7. 达到要求后，由当前会话的人格和模型生成最终回复。

同一群同一时间只运行一个判断任务。不同群的近期消息、回复间隔和执行状态彼此独立。

## 与 AstrBot 自带功能的区别

| 功能 | AstrBot 群聊上下文 / 主动回复 | 本插件 |
|---|---|---|
| 主要用途 | 为回答提供群聊背景，并可按概率主动回复 | 进一步判断普通群消息是否值得接话 |
| 最近消息 | 由 AstrBot 管理并提供给最终回复 | 维护少量内存记录，仅供参与判断 |
| 最终回复 | 使用当前会话配置 | 继续复用当前会话的人格、模型和上下文 |
| 直接唤醒 | 进入 AstrBot 正常回复流程 | 默认跳过，黑名单命中时除外 |

两者可以配合使用：AstrBot 提供群聊背景，本插件决定何时主动加入。

## 配置

| 设置 | 默认值 | 用途 |
|---|---:|---|
| 参与判断概率（%） | 15 | 普通群消息进入模型判断的机会；0 表示不随机参与，100 表示每条都判断 |
| 回复把握要求（%） | 80 | 判断结果达到该把握程度后才生成回复；数值越高越谨慎 |
| 判断使用的模型 | 跟随当前会话 | 负责判断是否值得接话 |
| 识别图片使用的模型 | AstrBot 默认图片描述模型 | 负责把群聊图片转换成文字描述 |
| 群白名单 | 空 | 限定插件在哪些群处理普通消息；空白表示不限制 |
| 群黑名单 | 空 | 阻止机器人响应指定群，优先于群白名单 |
| 机器人称呼 | 空 | 例如 `Denia,达妮娅`；正文出现这些称呼时跳过概率抽取 |
| 账号黑名单 | 空 | 填写发送者 QQ 号，阻止机器人响应该用户 |
| 参考最近消息数 | 10 | 判断是否参与时参考的近期群消息数量 |
| 等群聊说完（秒） | 2 | 未叫到机器人时等待群聊暂时安静后再判断；期间有新消息则重新计时，0 表示关闭 |
| 被叫到后保持参与（秒） | 120 | 被明确叫到或主动回复后，同一群内暂时跳过概率抽样；每次回复都会续期，0 表示关闭 |
| 主动回复间隔（秒） | 0 | 同一群两次主动回复之间的最短间隔；0 表示不限制 |
| 最长判断时间（秒） | 15 | 等待判断模型的最长时间 |
| 查看群聊图片 | 关闭 | 允许视觉模型读取参与判断的群聊图片 |
| 最多查看图片数 | 1 | 单条消息最多提交给视觉模型的图片数量 |
| 记录判断结果 | 关闭 | 在日志中记录判断结果、把握程度和简短原因 |

### 群范围与黑名单

群白名单接受群 ID 或完整 UMO，用于限定普通消息主动参与的范围。群黑名单同样支持这两种标识，并且优先级更高；命中后，普通消息和直接 @、引用、唤醒都会被拦截。

账号黑名单只比较消息发送者的账号。QQ/OneBot 下填写 QQ 号，不填昵称或 `/sid` 返回的完整会话标识。普通成员仅仅 @ 了某个黑名单账号，不会因此被连带屏蔽。

### 机器人称呼

机器人称呼用于识别没有形成真实 @ 消息段的文本，例如复制出来的 `@Denia 你好`。匹配不区分大小写，只要正文包含其中一个称呼，就会跳过概率抽取并进入模型判断。

称呼尽量使用完整名称；单字称呼容易在普通聊天中误触发。命中称呼不等于一定回复，判断模型仍会检查这句话是否真的在与机器人交流、是否值得回应。

### 等待、模型与回复间隔

判断模型留空时，插件使用当前会话的聊天模型。视觉模型留空时，会尝试使用 AstrBot 配置的默认图片描述模型。

“等群聊说完”只影响没有明确叫到机器人的普通群消息。直接 @、引用和唤醒仍立即交给 AstrBot；正文中出现已配置的机器人称呼时，也会立即进入本插件的模型判断。不同群分别计时。被较新消息替换的旧消息仍会保留在近期消息中，供最新消息的判断参考。

被真实 @、引用或唤醒后，机器人会立即在该群短时间保持参与。文本中出现配置的机器人称呼时仍会立即进入判断，但只有判断为需要回复且达到把握要求后，才开始或续期。保持参与期间，普通消息不再经过随机概率抽样，但仍会等待群聊暂时安静，并由判断模型决定是否真的回复；每次实际触发回复都会重新计时，判断为忽略、把握不足、超时或报错时不会续期。该状态只保存在内存中，按群隔离，超时或重启后自动消失。

回复间隔在调用判断模型之前检查，并从上一次由本插件触发回复时开始计算。直接 @、引用和唤醒走 AstrBot 正常流程，不受这个间隔影响；黑名单仍然有效。

## 图片与模型

开启“查看群聊图片”后，原图先发送给视觉模型，得到的文字描述再交给判断模型。判断模型据此决定是否参与，不直接读取原图。确定回复后，原图会交给当前会话模型；如有图片描述，也会一并提供。

图片准备或描述失败时，插件仍可根据正文和“消息包含图片”这一信息继续判断。启用图片查看可能增加模型费用，也意味着图片会发送给所选视觉模型。无论是否开启该选项，只要插件决定回应一条带图消息，原图都会交给当前会话模型生成最终内容；请根据所用服务商的隐私政策决定是否使用这项能力。

## 失败时会怎样

- 判断超时、报错、输出格式不正确或把握不足时，本次不主动回复；
- 当前群没有活动会话时，不创建新会话；
- 同一群已有判断任务时，后续普通消息不会排队补答；
- 近期消息、回复时间和运行锁保存在内存中，AstrBot 重启后会清空。

## 安装

在 AstrBot WebUI 打开“插件 → 插件市场”，搜索“群聊主动回复管理”或 `astrbot_plugin_group_reply_gate`。

如果插件市场尚未收录，也可以在安装框中输入仓库地址：

```text
https://github.com/kano0222/astrbot_plugin_group_reply_gate
```

安装后启用插件，再按需设置群范围、模型和回复频率。

常用检查：

```powershell
python -m pytest -q

ruff format --check .

```

推送到 `main` 或提交 Pull Request 时，GitHub Actions 会运行 Ruff 和 pytest。推送与 `metadata.yaml` 版本一致的 `v*` 标签后，工作流会构建可安装 ZIP，并创建对应的 GitHub Release。
